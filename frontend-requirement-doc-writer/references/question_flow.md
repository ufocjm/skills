# 详细提问流程（防跑偏版）

## 1. 目标

1. 在写文档前锁定需求边界与业务语义。
2. 在实现前暴露高风险缺陷点，降低研发阶段 bug。
3. 将“不可自动决策项”全部转为明确问题并闭环。
4. 让输出文档可被下游 AI 稳定解析并直接执行。

## 2. 提问顺序（不可跳步）

1. 业务背景与目标确认
2. 页面与流程确认
3. 接口文档定位与字段确认
4. 列表与按钮确认
5. 字段展示与校验确认
6. 实施阶段与发布回滚确认

## 3. 业务背景提问组

1. 这次需求要解决的核心问题是什么？
2. 面向哪些用户角色？主要触发场景是什么？
3. 成功上线后如何判断“达标”？指标是什么？
4. 当前版本明确不做什么？
5. 有哪些强约束（时间、合规、依赖系统）？
6. 下游 AI 的任务目标是什么（代码生成/测试生成/联调脚本/评审）？

## 4. 业务理解复述规则

1. 每次完成业务背景提问后，先输出“业务理解复述”。
2. 只有在需求方确认“复述正确”后才能进入下一组提问。
3. 若复述被否定，必须先修正理解再继续。

## 5. 接口提问组

1. 接口文档路径或系统地址在哪里？
2. 接口版本与负责人是谁？
3. 每个关键字段的业务含义是什么？
4. 枚举值、默认值、空值语义是什么？
5. 单位、精度、时区、脱敏、国际化规则是什么？
6. 错误码与失败重试策略是什么？
7. 字段类型是否可机器解析（避免“对象/文本”这类模糊类型）？

## 6. 列表与按钮提问组

1. 列表每列的含义、排序、筛选规则是什么？
2. 需要哪些按钮？每个按钮的业务动作是什么？
3. 按钮显示条件、禁用条件、权限条件是什么？
4. 点击后是否触发状态变更、通知、任务等副作用？
5. 是否需要二次确认、撤销、补偿或回滚？

## 7. 字段展示提问组

1. 字段用何种组件展示（文本、标签、金额、日期、状态色等）？
2. 长文本、空值、非法值、超长值如何展示？
3. 是否有格式转换规则（小数位、千分位、时区转换）？
4. 是否需要脱敏与权限分级展示？

## 8. 实施阶段提问组

1. 实施里程碑和排期约束是什么？
2. 前端开发任务如何拆解（页面、组件、状态管理）？
3. 联调顺序、测试范围、发布窗口如何安排？
4. 回滚触发条件与补偿方案是什么？
5. 每阶段进入下一阶段的门禁条件是什么？
6. 每个任务的 `TASK-ID`、依赖、输入、输出、完成定义是否齐全？

## 9. 机器可解析提问组

1. `REQ-ID`、`API-ID`、`TASK-ID`、`TEST-ID` 编号规则是否确认？
2. JSON 附录是否有固定字段约束？
3. 是否要求禁止模糊词作为执行依据？
4. 待确认问题是否区分 `BLOCKER` 与 `NON-BLOCKER`？

## 10. 停止提问条件

1. 业务目标、范围、接口、交互、实施路径全部可执行。
2. 所有高风险项已有明确决策或被标记为待确认。
3. 验收标准已可观察、可验证、可追溯。
4. 机器可解析附录字段完整，且可由 JSON 解析器读取。

## 11. 无法确认时的处理

1. 不猜测，不补脑，不隐式默认高风险规则。
2. 将问题写入 `## 15. 待确认问题（必须答复）`。
3. 若缺失项阻断开发，明确标注“阻断项”。
4. 若缺失项影响机器解析，明确标注为 `BLOCKER`。
