# 风险闸门与阻断条件

## 1. 目的

在需求阶段提前阻断高风险不确定项，避免研发阶段返工、线上缺陷与发布事故。

## 2. 风险等级

1. 高风险：权限、状态流转、不可逆操作、资金/库存影响、回滚不可行。
2. 中风险：字段语义不清、按钮副作用不清、验收标准不可测、JSON 结构不完整。
3. 低风险：文案、样式微调、非关键展示细节。

## 3. 阻断规则（必须执行）

1. 缺少业务成功指标：阻断文档定稿。
2. 缺少关键接口字段语义：阻断联调与开发结论。
3. 按钮副作用不明：阻断交互与状态设计定稿。
4. 权限模型不明：阻断发布结论。
5. 缺少回滚与补偿方案：阻断上线结论。
6. 验收标准不可验证：阻断交付结论。
7. 缺少机器可解析附录或 JSON 非法：阻断交付结论。

## 4. 风险记录格式

每个风险条目至少包含：

1. 风险 ID
2. 风险描述
3. 影响范围
4. 触发条件
5. 当前状态（Open / Mitigated / Closed）
6. 责任人
7. 处置策略

## 5. 默认处置策略

1. 高风险项：必须询问并拿到明确答复。
2. 中风险项：可先给推荐默认值，但必须显式确认。
3. 低风险项：可自动决策并在文档中声明默认值。
4. 机器可解析风险：必须通过结构检查后才能关闭风险。

## 6. 结论输出规则

1. 当存在任一阻断项时，只能输出“待确认后可继续”。
2. 当所有阻断项关闭后，才能输出“可进入实施阶段”。
