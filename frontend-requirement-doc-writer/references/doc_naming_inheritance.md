# doc 命名风格继承规则

## 1. 扫描顺序

1. 优先扫描 `./doc`。
2. 若不存在，再扫描 `./docs`。
3. 若都不存在，使用默认命名规则。

## 2. 识别维度

1. 文件名结构：`topic.md`、`topic_v2.md`、`v2_topic.md`、`topic-requirement.md` 等。
2. 分隔符：下划线、连字符、无分隔。
3. 版本表达：`v1`、`V1`、`_v1`、`-v1`、日期后缀。
4. 语言风格：中文、英文、拼音。
5. 目录结构：平铺、按模块目录、按版本目录。

## 3. 继承策略

1. 按命名模式分组并统计数量，优先选择数量最多的模式。
2. 若数量并列，选择“最近修改时间（mtime）最新文件”所属模式。
3. 若仍并列，直接选择字典序最小模式。
4. 新文档路径、文件名、版本写法保持一致。
5. 若用户明确指定路径或文件名，用户指定优先。

## 4. 冲突处理

1. 当存在多套风格时，按“数量最多 -> 最新 mtime -> 字典序”执行，并在文档写明假设。
2. 若样本不足（少于 2 个），回退到默认命名。

## 5. 默认命名（回退）

1. 默认目录：`doc/`
2. 默认文件：`<topic>_v1.md`
3. 主题使用小写英文短横线形式（如 `order-refund`）
4. 若默认目录不存在，先创建目录再写入文件。
