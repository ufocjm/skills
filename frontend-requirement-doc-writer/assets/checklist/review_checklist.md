# 前端需求研发文档检查清单

## 1. 结构完整性

1. [ ] 已使用固定结构：`1 个一级标题（#） + 16 个二级章节（##）`，且顺序一致。
2. [ ] 所有标题均为中文。
3. [ ] 信息不足处已使用 `TODO:` 明确标注。

## 2. 上下文与命名一致性

1. [ ] 已扫描 `doc/` 或 `docs/`。
2. [ ] 新文档路径与命名继承现有风格。
3. [ ] 若风格冲突，已按“数量最多 -> 最新 mtime -> 语义最接近/字典序”规则选择并记录假设。

## 3. 深度提问充分性

1. [ ] 已完成业务背景提问并输出理解复述。
2. [ ] 已确认接口文档位置并完成字段级追问。
3. [ ] 已逐项确认列表按钮语义与副作用。
4. [ ] 已确认字段展示、格式、校验、异常规则。

## 4. 实施阶段质量

1. [ ] `## 12. 详细实施阶段` 的 8 个子章节完整。
2. [ ] 每阶段都包含任务内容与门禁条件。
3. [ ] 联调、测试、发布、回滚步骤可执行。

## 5. 风险与验收

1. [ ] 高风险项已识别并记录处理策略。
2. [ ] 阻断项未关闭时未输出“可直接上线”结论。
3. [ ] 验收标准可观察、可测试、可追溯到需求与接口字段。

## 6. 输出结论

1. [ ] 若存在阻断项，结论为“待确认后继续”。
2. [ ] 若无阻断项，结论为“可进入实施阶段”。
